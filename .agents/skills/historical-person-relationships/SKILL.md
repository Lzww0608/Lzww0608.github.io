# 历史人物关系

关系图用于查阅一个人物的史载关系。用户明确要求先搜索并选择人物，选中后只显示该人物的直接关系；默认页面、未选中状态和清空后都不显示全体人物总图。

## 统一人物与关系资料

- 复用 [人物目录](../../../frontend/src/person-catalog.ts) 的 `catalogPeople` 和人物稳定 ID。皇帝与专题共用成员只能有一个身份；姓名、别名或帝号不是新 ID，不重复建立李嗣源、李存勖等已有人物。
- [关系注册表](../../../frontend/src/relationships.ts) 是关系事实的唯一来源。人物节点从统一人物目录派生；仅为理解已核验关系而需要的人物可登记为有来源说明的关联节点，不能借此恢复五代之外的朝代入口。人物索引与候选范围沿用 `displayedDynasties` 和现有项目约定。
- 新增人物专题复用 `personTopics`，同时接入 `content/person-passages.mjs` 的 `loadPassagePeople`；前端搜索／图节点与后端片段索引须覆盖同一组唯一人物。专题共用既有人物只复用 `memberIds`，不在 `people` 重复身份；用 `relationshipSubject` 显示真实主将，不把新专题套用李克用关系主语。真实异名与具体任职证据可以独立保存，但图上的关系事实仍只登记一次。
- 新增人物必须进入统一目录，随即自动成为可搜索、可选中的关系图节点；不维护另一份手写人物清单。人物尚无核验关系时，仍能打开个人图并明确显示“暂无已核验关系”，不编造连线补齐。
- 新增关系只登记一次，包含稳定关系 `id`、两端人物 ID `from` / `to`、`kind`、准确标签及证据；按 `from === personId || to === personId` 派生双方的直接关系，复用 `buildRelationshipNodes`、`getRelationshipNeighborhood` 及现有包装函数。双方个人图与关系列表必须同时出现该事实，不复制每人的关系数组、单独补另一端或缓存一份独立图。
- 直接邻接图只包含所选人物、与其直接相连的节点及这些连线；不递归展开全网，也不额外绘出邻居之间与所选人物无关的边。布局按当前节点和边计算，不为具体人物手写坐标、限定人物 ID 或固定“25 人”等当前规模；通用布局尺寸不受此限制。
- 保持节点及关系 ID 唯一、两端存在、邻接节点去重、关系无重复。同一人物对的亲属、收养与皇位交接可以是不同事实；不能把同一事实反向复制成第二条边。关系资料变动经同一派生逻辑更新所有受影响的个人图。

## 先核验史料再建立关系

- 逐条读取已保存的繁体原文，核对人物身份、上下文及版本；关系证据记录来源 `chapterId`、稳定 `paragraphId`、来源标题和该段中连续、逐字一致的繁体 `excerpt`。引文存在只能证明绑定有效，还要确认它确实支持标签与说明。
- 太祖、高祖、武皇、帝等称呼须结合本书、本卷和上下文辨认人物，不能把孤立帝号、同姓、赐名、同传出现或专题成员身份自动解释为某种关系。未经核验的推测、后世演义和共同固定排行不能进入史实关系注册表。
- 区分 `kinship` 亲属／姻亲、`adoption` 收养／养育、`service` 任职／部将、`conflict` 冲突／交恶、`succession` 皇位交接。亲子与养子、收养与具体养育者、赐姓名与收养、任职与父子、帝位取代与正常传位分别保留，不因连图方便而合并。
- 有方向的事实保持含义：父母或养育者 → 子女、主将或任命者 → 部属、前任 → 后任。反向查阅时保留同一条边和原始方向，可用准确的反向称谓解释。兄弟、交恶等对等关系不将布局方向当成历史因果；事件行为人的方向另由证据与说明表达。
- 对新旧史差异、传闻归属、发生时期和多层关系分别写清说明，保留各自证据；不得拼接异说成一条确定叙事。十三太保成员不一概称为李克用养子，李嗣昭的李克柔养育关系及康君立、史敬思的部将身份沿用核验结果。
- 缺少依据时保持无边状态或待核验资料，不为了图形连通自动猜测关系。自动生成的是个人视图，不是历史事实。

## 搜索、个人图与阅读

- 默认只提供人物搜索入口；查询按资料中的姓名和别名返回候选，输入文本本身不等于选择人物。用户明确选择一个候选后，才显示该人物的 SVG 直接关系图和有出处的关系列表；人物详情中的关系入口也视为明确选中该人物。
- 切换人物重新派生其图；清空选择返回未选中空态，不回退到总图。无候选、未选人物、人物暂无已核验关系，以及筛选后无关系使用各自清晰说明，不能把筛选隐藏的关系说成尚未核验。
- 图节点、候选与关系操作支持键盘和可见焦点，图的文字列表提供等效阅读与操作。缩放、窄屏及多条边布局不得遮挡文字或使出处入口不可达。沿用 [统一配色](../../../frontend/src/appearance.css)，核对纸笺、青瓷、夜读的文字、线条与焦点可读性；相关侧栏复用项目的可收起组件。
- 引文复用 [古文阅读技能](../historical-text-reading/SKILL.md) 的共用繁简转换及阅读偏好：繁体证据保存原样，简体只转换显示，切回繁体直接读取证据底本。核对专名与歧义字，不改写归档、稳定段落 ID 或已发布译文。
- “阅读出处”复用 [Reader](../../../frontend/src/Reader.tsx) 和现有章节／段落定位入口，打开证据绑定的具体章节并定位具体段落；不跳到任意主卷后让用户自行查找。人物主阅读入口仍复用 [library](../../../frontend/src/library.ts) 的 `preferredChapterForPerson`。

## 人物记载索引

- 新增人物或记载时同时维护 [共享片段索引](../../../content/person-passages/index.json)，扫描全部当前归档，包括其他人物传记；核对异名、帝号、前后文承接与分传边界，不能把同名词、地名或孤立帝号直接归给一个人。以 [可复现规则](../../../content/person-passages/rules.json) 与 [生成器](../../../scripts/index-person-passages.mjs) 保存核对依据，新增歧义排除须有来源位置并加回归检查。
- 一个完整原文段落只登记一个共享片段，人物与片段为多对多关联；新增已核对记载后，双方及其他参与人物的文献汇总自动读取同一记录，不复制正文/译文或每人的独立 slice。原文修订与校验不匹配时暂停旧关联，全文阅读仍可定位原章节。
- 关系事实仍须单独核验，人物共同出现在片段中不等于二者有亲属、任职或交恶关系。关系引文继续绑定具体章节/段落；文献入口默认进入人物片段汇总，而完整传记入口及原文出处保留既有 Reader。遵循 [古文阅读技能](../historical-text-reading/SKILL.md) 的文白对齐、繁简、版本与校订要求。

## 复核已有归属

复核关系时除核对逐字引文，还要核对它是否支持直接关系。河东军整体统属或专题成员身份不能证明某人是李克用直接任命的部将；只明确李克柔、李嗣昭的引文须保留真实主将，不强造最高领主的直接边。人物记载检索中的《周世宗实录》等引用书名不算柴荣事迹；排除书名后仍有实际人物行为的段落要保留。修正规则后核对精确关联差异、双方关系图及隔离数据库索引回滚／幂等；私有复核清单按古文阅读技能保留证据与原译版本绑定。

## 验证与范围

- 更新人物或关系后，沿用现有 `node:test` 检查节点、边 ID 与两端完整性、逐字引文绑定、正反两端邻接关系均出现一次，以及中心图没有无关边。增加一个人物或一条关系后，验证统一派生能直接反映变化，而不修改每人的图；无关系人物应保留单节点与说明。
- 浏览器核对：初次进入不绘制总图；输入只显示候选；选中后只绘制个人直接关系；切换人物更新图；清空回到空态。验证姓名／别名搜索、无结果、无关系、关系筛选、键盘、窄屏、三种配色、繁简引文和具体出处段落定位。
- 前端修改按项目要求运行 `npm run build`、`npm test`、`npm run test:sites`。部署后还需按已获授权的流程在线验证，不能用本地检查代替。
- 本技能用于前端人物资料、关系展示和来源核验，不授权数据库写入、批量导入、修改原文或译文、推送或发布。任务限定前端时，保留该边界；需要新增史料或其他工作时按用户实际授权和根目录 `AGENTS.md` 单独处理。

## 内容备份

新增或修订史料、人物、译文、关系及片段／句译索引，或导出所有者校订后的公开副本时，完成内容检查和主项目提交后，执行 [内容备份技能](../history-content-backup/SKILL.md) 的指定仓库备份及 push 流程。用户已授权此后续工作流；本技能的其他范围限制仍以当前用户要求为准。纯界面样式修改不触发整库备份。
