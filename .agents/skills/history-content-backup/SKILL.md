# 历史内容备份

用户于 2026-10-10 指定 `/Users/lzww/history_backup` 为备份仓库，固定远端为 `https://github.com/Lzww0608/history_backup.git`，并要求后续新增内容自动备份及 push。用户随后将该仓库改为 private，明确要求直接保存未加密数据库，不使用加密或密钥。该持续授权适用于这一指定私有仓库，不需每轮重新询问；它不扩大人物、译文、数据库修改或网站发布的任务范围。

## 触发范围

- 新增或修订人物、史料原文、全文译文、独立句译、人物关系或记载片段、句译范围索引时，将本流程纳入本次内容工作的完成条件。
- 所有者在线校订产生新译文版本后，完成公开副本导出及对应索引复核，再备份新状态。仅打开校订表单没有产生新内容。
- 纯 UI 布局、颜色或控件修改不要求反复制作完整数据库备份。这里的“自动”指每次内容开发／修订的工作流，不创建用户未要求的定时任务、后台监听或其他仓库同步。

## 执行顺序

1. 重大数据库写入前，按原有流程先做本机备份和隔离批次验证，再运行 `npm run backup:github --prefix backend -- --baseline`，将当时正式库与已提交 HEAD 备份、push 并验证成功。此模式允许已有未提交开发改动，但不包含它们，清单标为 `sourceState: committed-baseline`；不得为预备份强行提交用户工作或声称包含未提交新资料。变更后的第二次备份不能替代变更前备份，测试不覆盖正式库。
2. 完成已授权的发布、全文与独立句译公开副本导出、人物及句译索引更新和相关项目检查。保持原文、稳定 ID、旧版本、真实来源与审核状态；私有数据库备份不等于公开发布草稿。
3. 将本次源码、史料、公开译文及显示索引提交到主项目。备份源码使用 `git archive HEAD`，尚未提交的改动不会进入快照；默认备份模式要求受版本管理的改动与新增源码已提交，仅兼容忽略用户根目录未跟踪的 `package.json` / `package-lock.json`。不要把旧 HEAD 说成包含本次新内容。
4. 在主项目根目录执行：

   ```sh
   npm run backup:github --prefix backend
   ```

   复用 [备份脚本](../../../backend/scripts/backup-to-github.mjs)。新快照使用 `schemaVersion: 2`，包含 `project.tar.gz`、未加密的 PostgreSQL custom 格式 `database.dump`、`manifest.json` 和 `verification.json`。清单记录源提交、数据库状态、内容计数及文件 SHA-256；读回实际快照文件，在独立数据库完整恢复，比对全部表行哈希、结构和身份序列，通过后才 commit、push 并验证远端提交。
5. 向备份仓库写入数据库文件前，以及每次 push 前，都核对固定远端的 GitHub 可见性为 `private`。如果显示 public、无法确认或返回未知状态，立即停止，不向仓库放入或推送数据库文件，也不改为其他目标。核对本地路径、fetch／push 远端与分支，保留既有用户文件和提交，不重建仓库或强制推送。
6. 检查成功结果与远端对应提交，核对源提交、数据库恢复验证和文件哈希，再报告备份提交链接。只生成本地文件、只提交未 push、恢复检查失败或无法证实远端提交，都不算完成异地备份。内容和源提交一致时复用已有快照；推送失败重试已提交快照，不强制推送，不跳过私有状态检查。

## 数据范围与恢复

- 未加密数据库只允许进入用户指定、已确认私有的 `history_backup`。源码与史料沿原有许可证、署名和来源保存；数据库连接配置、所有者密码文件、隧道身份、日志及整个 `backend/.local/` 不进入源码包、公开主项目或网站。原文、译文、草稿及版本历史作为正式数据库内容完整备份。所有者校核清单、证据、处理状态和事件历史同样只进入该私有数据库快照，不导出到公开网站或源码包；恢复后重施私有校核表及窄函数权限。
- 默认备份、`--baseline` 和 `--verify` 均不需要密钥；不再使用解密命令、密钥环境变量，也不要求用户保存密钥。旧加密快照转换为对应未加密快照后仍需逐个核验恢复，保留既有 Git 提交历史，不为转换改写或强推历史。
- 恢复时先阅读 [备份仓库 RESTORE.md](https://github.com/Lzww0608/history_backup/blob/main/RESTORE.md)。用 `npm run backup:github --prefix backend -- --verify <snapshot-id>` 核对清单与文件哈希，并在独立数据库完整恢复；不能只数几张表或直接覆盖正式库。在新机器恢复后，按说明重新配置只读／校订账户与隧道。
- `HISTORY_BACKUP_REPO` 只可指定同一固定远端仓库的另一 checkout，不能据此授权新的 GitHub 目标。

阅读和人物内容分别沿 [古文阅读技能](../historical-text-reading/SKILL.md) 与 [人物关系技能](../historical-person-relationships/SKILL.md) 的版本及证据约定。备份完成后，网站部署与线上验证仍按当前任务要求执行；备份成功不能代替网站上线。
