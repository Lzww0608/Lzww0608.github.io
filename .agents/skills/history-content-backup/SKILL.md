# 历史内容备份

用户于 2026-10-10 指定 `/Users/lzww/history_backup` 为备份仓库，远端为 `https://github.com/Lzww0608/history_backup.git`，并明确要求后续新增内容自动备份并 push。该持续授权适用于这一仓库的内容备份，不需每轮重新询问。它不扩大人物、译文、数据库修改或网站发布的任务范围。

## 触发范围

- 新增或修订人物、史料原文、全文译文、独立句译、人物关系或记载片段、句译范围索引时，将本流程纳入本次内容工作的完成条件。
- 所有者在线校订产生新译文版本后，完成公开副本导出及对应索引复核，再备份新状态。仅打开校订表单没有产生新内容。
- 纯 UI 布局、颜色或控件修改不要求反复制作完整数据库备份。这里的“自动”指每次内容开发／修订的工作流，不创建用户未要求的定时任务、后台监听或其他仓库同步。

## 执行顺序

1. 重大数据库写入前，按原有流程先做本机备份和隔离批次验证，再运行 `npm run backup:github --prefix backend -- --baseline`，将当时正式库与已提交 HEAD 备份、push 并验证成功。此模式允许已有未提交开发改动，但不包含它们，清单标为 `sourceState: committed-baseline`；不得为预备份强行提交用户工作或声称包含未提交新资料。变更后的第二次备份不能替代这份变更前备份，测试不覆盖正式库。
2. 完成已授权的发布、全文与独立句译公开副本导出、人物及句译索引更新和相关项目检查。保持原文、稳定 ID、旧版本、真实来源与审核状态；不能为了备份临时公开草稿。
3. 将本次源码、史料、公开译文及显示索引提交到主项目。备份源码使用 `git archive HEAD`，尚未提交的改动不会进入这一快照；默认备份模式要求受版本管理的改动与新增源码已提交，仅兼容忽略用户根目录未跟踪的 `package.json` / `package-lock.json`。不要把旧 HEAD 说成包含本次新内容。
4. 在主项目根目录执行：

   ```sh
   npm run backup:github --prefix backend
   ```

   复用 [备份脚本](../../../backend/scripts/backup-to-github.mjs)，它导出正式库并加密，生成已提交项目快照与带版本、计数和 SHA-256 的清单，再读回已写出的加密包、验证解密结果并在独立数据库完整恢复核验；全部通过后才在指定备份仓库 commit 并 push。变更前／后按这一入口各保留已验证状态。核对本地路径与远端确实属于用户指定仓库；保留其既有历史和用户文件，不重建仓库或强制推送。
5. 检查脚本成功结果及远端对应提交，核对清单的主项目提交、数据库恢复验证和文件哈希，再报告备份提交链接。只生成本地文件、只提交未 push、恢复检查失败或无法证实远端提交，都不算完成异地备份。定位具体失败后再续做；内容和源提交一致时复用已有快照，推送失败则重试已提交快照，不重建密钥、不强制推送。不要因任务困难而跳过备份或伪造成功。

## 私密资料与恢复

- 该 GitHub 仓库目前公开。源码与公开史料按原有许可证、署名和来源保存；数据库含草稿、版本历史等私有内容，只上传 AES-256-GCM 加密后的 dump。不得上传明文 dump、数据库连接凭据、所有者校订密码、隧道身份、日志或整个 `backend/.local/`。
- 密钥仅保存在主项目本机 `backend/.local/backup-key.bin`，权限为 `0600`，不进入任何 Git 仓库、清单或公开日志。不输出密钥正文，不为下一次备份随意覆盖密钥。用户需要另存一份离线密钥才能在 Mac 丢失后恢复加密库；报告其路径和这一恢复依赖，不替用户把密钥上传 GitHub。
- 恢复时先阅读备份仓库的恢复说明。用 `npm run backup:github --prefix backend -- --verify <snapshot-id>` 核对已有快照的加密包、源码包、清单及解密后的独立数据库恢复；验证需核对全部表行哈希及身份序列，不能只数几张表。
- 如需单独取出数据库，运行 `npm run backup:github --prefix backend -- --decrypt <snapshot-id> --output <本项目 backend/.local/backups/文件名.dump>`；明文只写私有目录，后续恢复先在独立数据库进行，不直接覆盖正式库。另存密钥可由 `HISTORY_BACKUP_KEY_FILE` 指定，值及内容不输出。`HISTORY_BACKUP_REPO` 只可指定同一远端仓库的另一 checkout，不能据此授权新 GitHub 目标。
- 密钥、密钥标识和文件哈希是不同信息，清单不能代替密钥。在新机器恢复后，按备份仓库说明重新配置只读／校订账户及隧道，不能将旧凭据放入公开仓库。

阅读和人物内容分别沿 [古文阅读技能](../historical-text-reading/SKILL.md) 与 [人物关系技能](../historical-person-relationships/SKILL.md) 的版本及证据约定。备份完成后，网站部署与线上验证仍按当前任务要求执行；GitHub 备份成功不能代替网站上线。
