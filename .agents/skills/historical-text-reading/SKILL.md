# 古文史料阅读

项目约定：现有和后续所有古文阅读入口都提供繁体／简体切换，并记住选择。当前项目为 React + TypeScript + Vite 前端、Node HTTP 只读 API 和 PostgreSQL；新增史料沿用现有结构。

## 共用阅读功能

- 复用 [Reader](../../../frontend/src/Reader.tsx)、[阅读偏好 hook](../../../frontend/src/use-original-script.ts) 和 [显示转换模块](../../../frontend/src/original-script.ts)。API 与随站静态归档都经过同一阅读组件；不要为单本书复制一套转换或遗漏切换按钮。
- 默认显示保存的繁体底本；简体是自动转换的阅读显示。切回繁体直接读取底本，不能从简体反向转换：發／髮等文字会合并，无法无损还原。
- 保持跨卷、跨书、刷新后的选择，沿用版本化偏好键 `ancient-history:original-script:v1`。浏览器禁止储存偏好时，阅读与切换仍须可用。
- 转换字典仅在需要简体时加载，随站发布；不要引入外部在线转换服务。加载失败保留可读的繁体原文并允许重试；离开章节或切回繁体时，过期异步结果不能覆盖当前选择。
- 按实际显示设置正文语言 `zh-Hant` / `zh-Hans`。切换按钮显示当前选择，支持键盘，窄屏不遮挡字号及章节目录。

## 原文标题显示

- 阅读页卷标题，以及底本中的年号、序、分篇和小节标题，使用比正文更大的字号和 700 字重，沿实际层级使用 h1/h2/h3/h4 等标题元素。正文中的标题随阅读字号放大，窄屏允许自然换行。
- 复用 [标题索引生成器](../../../scripts/index-reading-headings.py) 和 [显示分类模块](../../../frontend/src/reading-headings.ts)。来源 h2–h6 保留层级；《资治通鉴》的旧排版年号、卷名和纪名，以及《五代史阙文》的“◇”小节标记，按已核对的明确规则识别。不要仅因一句话短、含年号或人名就将普通叙事当作标题。
- predev/prebuild 使用 Python 3 从已保存来源自动生成独立显示索引，核对来源块与归档原文逐字一致；新增来源需保留可辨认的标题结构。不要为恢复排版重新抓取或覆盖现有底本。
- 按繁体规范原文、稳定段落 ID 和修订号判定标题，再转换显示文字，使繁简切换后的层级一致。API 原文或修订不同则不套用旧索引，待核对其来源后补充格式。标题样式不改变段落编号或译文。

## 底本、专名与译文

- 转换只派生显示文本，不修改数据库、API 响应或归档中的原文，不改变段落 ID、顺序、修订号、出处、校验值和署名。原文中的夹注、序文和校勘说明也保留并随正文切换。
- 复用 [转换字典配置](../../../frontend/src/script-converter.ts) 的 OpenCC 繁转简方案。新增古文时核对年号、人名、地名的歧义转换；通用转换可能把“乾祐／乾化”写为“干祐／干化”。有来源依据的例外在共用短语表中维护，并补充检查，不批量猜测或改写底本。
- 已发布的现代译文及译者署名原样显示，并保留其独立语言标记。繁简切换不等于翻译，不生成缺失译文，不显示草稿或与原文修订不匹配的译文。
- 公开归档位于 `content/five-dynasties/`；`frontend/public/history/` 是自动生成副本。遵守根目录 `AGENTS.md` 和 `frontend/AGENTS.md` 的来源、授权、稳定 ID 与校验约定。

## 人物片段阅读

- 人物文献入口汇总 `content/person-passages/index.json` 中属于该人物与文献的所有已核对片段，包括他人传记和编年、笔记中的记载；不以整卷 `subjects` 或主阅读卷冒充片段范围。新增人物或史料时重新生成并核对独立索引，复用 [索引生成器](../../../scripts/index-person-passages.mjs) 与 [完整性验证](../../../content/person-passages.mjs)。
- 第一版片段是相关完整段落，文白对照复用 [OriginalParagraph](../../../frontend/src/OriginalParagraph.tsx) 与现有译文记录；跨段省略处明确标出，提供完整章节和具体段落定位。部分句子与译文的字符范围不能互相套用，句级对齐需另存经核对、绑定具体原文/译文版本的范围。校订必须回到完整段落，不对截取文字覆盖整段译文。
- 每个范围绑定繁体底本、稳定段落 ID、原文修订和 SHA-256；原文变化时旧关联暂停，不能套用旧范围。片段原文、标题、繁简、译文署名和校核提示沿同一共享组件显示，不复制一套阅读实现。
- API 仅公开匹配原文的最新已发布译文，停机时使用随站索引和逐章副本。第一页建立人物/书籍/读取来源/结果集合的分页基准；变动后返回第一页，不能沿用另一来源的偏移。不得因静态副本仍有关联而覆盖成功 API 的暂停结果。
- 原文、旧译文、公开副本与校订历史均不因索引改变而改写；界面说明当前归档范围，不能宣称未归档全书已全部检索。

## 人物记载检索

- 使用 [共用检索模块](../../../content/passage-search.mts) 匹配所选人物的完整相关记载，按原文／已发布全文译文及文献筛选后再分页，不能只检索当前页。繁简转换仅派生检索文本；保留原字形直接匹配，防止语境转换漏字。正文、译文版本和段落ID不因检索改写，草稿、署名和校核提示不进入正文结果。
- API最新数据与静态副本沿同一规则，结果校验实际原译Unicode范围。查询、字段、人物、书、来源或结果版本变更需重置分页；成功API空结果或无法验证的检索响应不能被旧静态结果覆盖。
- 查询和字段进入人物记载地址，文献切换、刷新及上下文返回保持状态。高亮复用 [文本标记组件](../../../frontend/src/HighlightedText.tsx)，只增加mark，不插入HTML或破坏句译点击。繁简显示改变时对实际显示文本重算，并将底本命中经真实字形转换投到显示文字后合并，避免“憑藉”查“藉”切成“凭借”后丢失标记；原文范围不能套入译文。译文命中时初始展开，用户仍可收起。全文定位带合法内部返回入口并定位长段中真正命中位置，校订仍按完整段落处理。

## 单句译文弹窗

- 用户规定每个中文 `。` 是独立点击单位，包括引语及夹注内部的句号；复用 [句号切分与版本检查](../../../frontend/src/sentence-alignment.ts) 的 `splitPeriodSpans` 及 [句译加载器](../../../frontend/src/sentence-translations-loader.ts)。只高亮所点单位，弹窗范围须精确对应它，不能隐式回退为较大句组或整段。
- 末尾没有中文句号但以中文问号／叹号结束的完整句子也必须可点击：使用 `splitReadingSpans` 保留全部既有句号单位，仅细分该尾部的 `？／！` 终句；闭符号和空白归前句。无句末标点的普通未完尾文继续作为文本。多句尾部或夹有未完尾文时，逐语义核对连续译文切点并在 `content/sentence-alignments/tail-overrides/` 绑定原文修订、全文译文ID／版本与双SHA-256；生成 `tailSentences` 后同时核验父尾范围起点和末端。不能让多个问叹句共享整尾或整段弹窗。全站检查独立计数源标点，验证繁简显示与真实加载器，新增内容同样执行。
- 新制作译文时，宜在私有稿中逐原句号单位保存已核对的现代译文片段，再按原顺序拼成完整段落译文；标题、无句号尾文、引语、夹注和校勘也完整翻译。以全段上下文核对语义，不按现代句数相等或字符比例猜配；一个原句可对应数句现代汉语，但不能夹带下一原句。
- 发布并导出后，才以实际译文 ID、版本及原译文双 SHA-256 生成 `content/sentence-alignments/period-overrides/` 偏移，沿用 [生成器](../../../scripts/index-sentence-alignments.mjs) 核验完整连续范围；公开索引不复制正文，私有译稿不随站发布。旧文或新校订版本不匹配时暂停旧范围，未独立对齐时显示提示，整段译文只由用户明确展开。

- 当原译的诗文解释后置、意义交错或底本句号截断语气词／夹注官名而无法忠实连续截取时，另存已核对的独立句译，不改全文版本，也不扩大原文点击单位。按必要上下文明示“接前句”等；完整意义不可用未完省略片语冒充。私稿经授权的备份、隔离原子导入和公开发布后，使用 [单句导入器](../../../backend/scripts/import-sentence-translations.mjs) 和 [单句导出器](../../../backend/scripts/export-sentence-translations.mjs) 保存独立表及 `content/published-sentence-translations/`。草稿不上站，真实来源和审核状态不变。
- 单句补译绑定原文修订／SHA-256、精确原句范围、完整译文 ID／版本／SHA-256；显示索引另外引用补译 ID／版本／文本 SHA-256，读取再次核验。公开 API 仅返回仍匹配公开章节与最新已发布全文的补译；成功空结果或无效响应不能被旧静态副本覆盖。全文版本更新时旧范围与旧补译均暂停，重新语义核对后才能启用。
- 现有九部归档全部可点击单位，以及后续新增内容，都执行 [全站逐句覆盖检查](../../../scripts/check-sentence-coverage.mjs)：通过真实共用加载器检验每个句号单位的已发布独立译文，不能仅检查整段译文齐全或偏移结构正确。`npm run test:sentence-coverage` 已纳入前端 prebuild；无句末标点且非标题的普通尾文仍不造点击目标。

## 所有者校核与本地开发

- 复核由当前任务直接完成原文与已发布译文的语义对读，不把结构扫描、数量齐全或模型自评当成实际阅读。私有清单记录稳定段落、原译双校验值、实际译文版本、连续证据和处理结论；未读、已核对、保留异说、已修订及版本失效分别登记。仅承诺当前归档范围，缺卷不冒充全书已复核。古文省略主语、惟／唯限定宾语等结构须结合整段核验，不能只按字序反转施受关系；解释未定时保留原译和疑点，撤回错判也只能追加版本并更新清单与句译绑定，不能删除修订历史。
- 复用 `backend/db/006-owner-reviews.sql` 与受保护的 `/api/editor/reviews`，清单不进入公开 API、人物目录、静态副本或浏览器持久储存。数据库 reader 无私有表权限，editor 仅执行三项窄校核函数，不使用 `GRANT SELECT ON ALL TABLES` 或未来表默认 SELECT。恢复 `--no-acl` 后重施最小权限，撤销函数 PUBLIC EXECUTE。
- 发现确切错译时，通过本机 `reviews:correct` 追加当前 AI 来源译文的新版本，保留原文及旧版本；不覆盖所有者已改版本，不把工具复核写成 `humanReviewed: true`。同批次先做正式库备份和隔离恢复验证，再发布、导出、复核全部受影响句号与问叹尾句的范围／补译绑定和人物索引。连续局部改字仅能在已经核对的语义范围内重新定位，禁止字符比例猜配。
- 用户于 2026-10-11 明确授权仅本机开发跳过密码：独立 `npm run dev:local --prefix backend` 监听 `127.0.0.1:8791`，开发前端仅在 `DEV`、页面与 API 都为 loopback 时自动建立内存会话。正式 `8787`／Funnel 服务仍验密码；开发端口不加入隧道，不以生产环境变量或可伪造的 Origin 单独放开正式服务。请求核对真实 socket、Host 与本机 Origin，拒绝代理转发头。

## 新增主传的语义复核

新增完整主传继续按真实 `splitReadingSpans` 单位制作私有稿，包括夹注句号、问叹尾句、标题与非点击尾文，再按原顺序拼成全文。另一任务独立实际阅读每个原句与对应译文，根任务对读全文；必修建议采纳后重新读变更单位与上下文，私有报告绑定最终稿 SHA-256。结构齐全不能代替语义复核，稿件修改后旧批准哈希不可复用。 隔离验证收据同时绑定实际批次全文、底本修订、人物索引与批准稿的组合指纹；正式执行前重算匹配，隔离后任何输入变化都须重新验证。发布后以实际数据库原译、批次绑定和索引摘要复验，不把成功收据的布尔值单独当作同批证明。

李克用武皇纪等追尊本纪中，“庄宗即位后追谥”须区分登皇位与早年继承晋王；旧史落落与存勖各称长子的来源差别独立提示，不统一世系。派兵不增写本人亲自出战、接待安排不任意补施事；神异、三矢等明确引书和“世传”归属保持。书信训诂未定时结合全段暂释并保留疑点，不把古词字面猜义当定论。独立“数日”等片语明示接前句而不扩大点击范围。新增私有校核项绑定实际发布全文版本，在同一隔离批次验证后追加清单，公开静态副本继续不含私稿或校核清单。

## 验证

对相关修改运行前端构建、`npm test` 与 `npm run test:sites`。使用 [现有转换测试](../../../frontend/tests/original-script.test.mjs) 检查歧义文字、夹注、原文恢复和已发布译文不变；新增史料还需执行原有归档／后端检查。浏览器验证繁简切换、跨卷／跨书／刷新保留选择，以及窄屏布局；核对卷标题、年号标题与小节标题加大加粗，普通正文不被误判，繁简切换、字号调整后层级仍一致。部署沿用用户授权和项目发布流程；本 skill 不单独授权推送、发布或数据库写入。

## 内容备份

新增或修订史料、人物、译文、关系及片段／句译索引，或导出所有者校订后的公开副本时，完成内容检查和主项目提交后，执行 [内容备份技能](../history-content-backup/SKILL.md) 的指定仓库备份及 push 流程。用户已授权此后续工作流；本技能的其他范围限制仍以当前用户要求为准。纯界面样式修改不触发整库备份。

## 人物年表的出处与日期

- 年表保存于 `content/person-timelines/<personId>.json`，只引用现有章节、段落、原文修订、SHA-256和连续引文；通过共享 `content/person-timelines.mjs` 校验。以真实原文和已发布译文语义对读摘要，引用存在不等于事件事实正确，不因同传或关系边自动推断事件。
- 排序用西历年与原书记年、记月、记日的粒度分开。年号末月可能跨次年，核对历表时验证实际解析的年号／年／月；工具对不存在日期或超出年号范围的回退不得采纳。仅发布核准年份，原书记日保留，异说独立列证，不拼接成唯一日期。
- 生前身份、实际称帝、追尊与后世传闻分开；派将行动不改成本人亲征。李克用生前晋王，923年追尊在身后；李存勖908年承晋王、923年即帝位不同。
- API以同一快照解析全部主证与异说，仅取当前公开原文及最新匹配已发布全文译文，任一证据失效或缺译文暂停整事件。成功空或无效API响应不可由旧静态副本恢复，网络离线才读取经同规则核验的随站版本。
- 年表阅读出处定位真实原段并返回原事件，复用Reader、繁简、三配色、可收起目录、默认收起全文与独立句译，不按原文字位截现代译文。完成备份和同批隔离验证后仅追加007独立索引；旧原文、译文、句译和校订历史保持。主项目检查、提交、部署、线上核对与私有备份均是内容工作的完成条件。

用户随后要求全部人物年表及新增人物自动维护。新增／修改人物或补充相关史料时，在同一任务执行 [人物年表技能](../historical-person-timelines/SKILL.md)；覆盖检查缺项不能用空文档消除，保持原文和旧译文版本。

## 事件多史料对读

- 共享显示索引在 `content/event-comparisons/`，按事件阶段组织完整相关原段与有据差异；复用 `content/event-comparisons.mjs`、前端schema/loader及共用OriginalParagraph。不复制或覆盖原译，不按原文字位截现代译文，不把本传长段中的其他年份事件当作该战役当日。
- 逐项实际对读选取原段和当前公开全文，差异用连续原文绑定来源ID、原修订与SHA；数字口径、纪年异说、人物补记和叙事立场分开，不把未提及当作否认，不把同源夹注计成独立证据。独立实际审稿绑定最终文档SHA和实际全文ID/version/双SHA，私有报告不上站。只承诺已归档选取范围。
- 原译继续取已有只读章节API；成功HTTP空／失效／无效响应暂停相关来源及依赖结论，仅网络离线用对应随站章节。差异针对绑定底本，最新匹配已发布全文保持原样可读；原文变更后先重核引用及差异，不能套用旧说明。
